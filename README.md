# RayNeo Switch

在独立配置 App 中填写模型接口，通过 Vector 模块接管雷鸟 iO 的模型回答。

## 使用方法

1. 下载并安装 `RayNeoSwitch-0.1.9.apk`。已有单模型配置会自动显示在对应供应商的模型列表中。[下载页面](https://github.com/Soare02/RayNeoSwitch/releases/tag/v0.1.9)
2. 在 Vector 中启用 RayNeo Switch，作用域勾选雷鸟 AI，然后重新启动雷鸟 AI。
3. 打开 RayNeo Switch，填写供应商名称、API 地址、模型名称和对应的 API Key。
4. 点击“测试连接”，开启“使用自定义模型”，再点击“保存并使用”。
5. 保持眼镜与官方雷鸟 App 连接，正常唤醒眼镜提问。

点击“新增供应商”可以填写另一套配置，点击“保存并使用”后加入列表并切换到该供应商。点击“已保存的供应商”下方的按钮，从列表选择即可切换，下一次提问使用所选供应商的地址、模型和 Key。

修改当前供应商的名称、地址、Key、模型或开关后，点击“保存并使用”。存在未保存修改时，切换或新增会提示保存、放弃更改或取消。自定义模型开关为全局设置，关闭开关并保存后，下一次提问进入官方问答流程。

“删除供应商”会要求确认。删除当前供应商后使用列表中的第一个供应商，删除最后一个供应商后关闭自定义模型。

API 地址支持带 `/v1` 等前缀的服务地址，也支持完整的 `/chat/completions` 地址。模型名称填写中转站或服务商提供的模型 ID。请求采用 Chat Completions JSON 协议。

“测试连接”会向填写的模型发送一次简短请求，按服务商规则产生用量。

## 模型列表与切换

填写供应商的 API 地址和 Key 后，点击“获取模型列表”。可以在弹窗中搜索模型 ID，多选后点击“添加所选”，再点击“保存并使用”。获取列表时允许模型名称留空。手工填写模型 ID 后保存，同样会加入该供应商的模型列表。

列表请求采用 `GET /models` 和 Bearer 鉴权，读取响应 `data` 中的 `id`。地址为 `https://example.com/v1` 时请求 `/v1/models`，填写完整的 `/v1/chat/completions` 地址时也会定位到 `/v1/models`。搜索供应商有独立的地址和 Key。[模型列表接口文档](https://api-docs.deepseek.com/zh-cn/api/list-models/)

同一供应商的多个模型共用 API 地址和加密 Key。点击“选择模型”可以搜索并切换，下一次眼镜提问使用所选模型。各供应商记住自己最近选择的模型。存在表单修改或待保存的新模型时，选择结果会填入当前表单，点击“保存并使用”后生效。

保存新模型会合并该供应商已有的模型列表，并去除重复 ID。配置保存和模型切换使用同一事务更新当前模型及供应商列表。原来的单模型字段继续供运行缓存和旧调用使用。

## 联网搜索

首页点击“联网搜索”进入设置。在搜索方式列表中可以选择关闭、官方搜索或已保存的自定义搜索供应商。搜索配置全局共用，与模型供应商分别保存。未配置过搜索时默认关闭联网搜索。

### 官方搜索

由雷鸟按问题触发联网检索，模块等待官方返回资料，再调用当前选中的自定义模型。可用的来源引用和正文会作为参考资料传入模型。官方只返回回答时，模块使用标明来源的“官方回答参考”。模块状态会显示本轮取得的资料类型。

现有日志中的 `searchSummary` 提供搜索数量、耗时等统计。网页正文和完整来源的实际返回情况取决于官方服务。本轮验证了回调数据收集、串流回答合并、超时处理和模型上下文传递，眼镜端真实问答效果仍待实测。

官方等待与重试由雷鸟原生 SDK 执行，模块在收到官方最终结果、完成或错误回调后提交已有资料。0.1.9 已移除模块自设的 45 秒定时器。当前原版 1.0.25 的运行日志配置为 `deepThinkTimeout=60000`、`maxTimeoutRetries=1`、`timeoutDelayMs=5000`，这些参数对应原生云端等待与重试。

官方返回错误码 1008 时，模块标明原生等待超时。取得部分资料时带上中断说明，缺少资料或回答时向眼镜反馈错误。官方资料及回答参考会提交给当前模型供应商。

### 自定义搜索

点击“新增自定义搜索”，填写名称、工具基础地址、API Key、返回条数及可选搜索范围，再点击“保存并使用”。支持保存多个搜索供应商，并从搜索方式列表直接切换。API Key 使用 AndroidKeyStore 加密保存。

默认工具基础地址为 `https://api.deepseek.com/v1/tools`。模块自动拼接 `/search` 和 `/fetch`，两个接口共用该供应商的 Key，通过 Bearer 鉴权。也可以粘贴以 `/search` 或 `/fetch` 结尾的地址，保存时会归一为基础地址。兼容服务可以使用对应的工具路径前缀。[DeepSeek 搜索与抓取文档](https://api-docs.deepseek.com/zh-cn/guides/search/)

Search 请求携带 `query`、`ori_question`、`count` 和 `need_content`，从 `results` 读取标题、链接、正文和摘要。Fetch 请求携带 `url`，从响应读取 `title` 和 Markdown 格式的 `content`。这些资料会交给当前选中的自定义模型生成回答。

“搜索范围”会作为检索词后缀，可以填写 `site:example.com`、`-site:example.com`、`lang:zh`、`after:2026` 等服务支持的搜索语法。检索词按接口的 128 个 Unicode 字符限制截取，模型接收完整的原始问题。结果数量支持 1–50 条，传给模型的资料总长度及单篇长度有上限。

“请求网页正文”对应 Search 请求中的 `need_content`。已有正文的来源会直接使用该正文。

“补抓网页数量”默认为 3，支持 0–50，0 表示关闭自动补抓。搜索后，模块按排名挑选缺少正文的来源，最多同时抓取 3 篇。成功抓取的 Markdown 会代替对应的摘要。抓取失败时使用搜索返回的资料，并在模型参考中注明。单次抓取读取超时为 15 秒。传给模型的单篇正文最多 3,000 个 Unicode 字符，资料总长最多 24,000 个字符。

“测试搜索”会执行搜索和按配置补抓正文。“测试抓取”会将测试输入框中的网页 URL 交给 Fetch 接口，并显示标题和正文。网页地址支持最多 8,192 个 Unicode 字符的 HTTP/HTTPS URL。测试使用当前表单中的设置，各接口按服务商规则产生用量。

升级前保存的标准 `/search` 地址会自动识别基础地址，默认启用最多 3 篇补抓。旧版独立搜索路径会继续按原地址请求，填写工具基础地址后可以启用抓取。

搜索及抓取回归使用手机本地测试服务，覆盖请求参数、共用鉴权、正文传入模型、排名与去重、失败回退、并发抓取取消、旧配置迁移和设置界面。真实搜索服务及眼镜端完整问答仍待实测。

## 配置与锁屏使用

配置 App 保存设置后，会通过仅允许本应用签名发送的广播同步给雷鸟进程。模块把运行配置加密保存在雷鸟 App 的私有目录中，供后台及锁屏问答读取。

```text
/data/user/0/dev.rayneo.switcher/shared_prefs/model_config.xml
/data/user/0/com.rayneo.venus.pub/shared_prefs/rayneo_switch_runtime_config.xml
```

模型和搜索 API Key 均使用对应进程的 AndroidKeyStore AES-GCM 密钥加密。搜索供应商保存在配置 App 的 `search_config.xml` 中，当前模型及搜索配置通过同一个事务写入雷鸟进程的运行缓存。安装包从运行时配置取得接口凭证。

如果“模块状态”停在等待加载，先确认 Vector 的启用状态和作用域，再重新打开雷鸟 AI，然后打开 RayNeo Switch 并点击一次“保存并使用”。

## 回答完整性

模型请求使用服务商默认的输出长度设置。0.1.7 及更早版本固定发送 `max_tokens: 512`，长回答可能在模型生成阶段达到这个上限。0.1.8 移除了该参数，并将模型接口读取超时调整为 90 秒。

当前中转站的 50 行合成文本对照中，旧请求返回 `finish_reason=length`，恰好消耗 512 个输出 tokens，缺少最后一行及结束标记。修复后的正常入口返回 `finish_reason=stop`，收到 959 个字符及完整末尾标记。眼镜端升级后的长回答显示仍待实测。

模块读取 `finish_reason`。返回 `length`、内容过滤、资源中断等结束原因时，会保留当前回答并附加中断提示。模型返回空文本时会反馈错误。缺少结束原因字段的兼容接口可以继续返回文本。

“模块状态”及模块诊断日志记录模型返回字符数、结束原因、输出 token 数和服务商提供的思考 token 数。诊断信息使用长度和状态数据。自定义模型的完整响应通过原来的 NLP 显示回调发送到眼镜，官方完成回调由模块接管。

## 源码构建

构建脚本适用于 Windows，需要 JDK 17、Android API 36、Android Build Tools 36 和 Xposed API 82。脚本使用 `C:\Program Files\Java\jdk-17` 下的 JDK。

在源码目录执行以下命令，创建本机构建配置。

```powershell
New-Item -ItemType Directory -Path .local -Force
Copy-Item android_build_paths.example.json .local/android_build_paths.json
```

将 `.local/android_build_paths.json` 的三个示例路径分别改为本机的 Android `android.jar`、Build Tools `aapt2.exe` 和 Xposed API 82 JAR 的实际路径，然后构建。

```powershell
python build.py
```

首次构建会在 `.local/rayneo-switch-development.jks` 生成本机开发签名，默认别名为 `rayneo-switch`，库密码和密钥密码均为 `android`。后续构建使用同一密钥，以便覆盖安装本机签名的版本。安装已发布 APK 后，覆盖安装需要使用与该 APK 相同的签名。

构建产物位于带时间戳的 `build` 目录，`latest_build.json` 记录最新 APK 的路径、SHA-256 和大小。本机依赖配置、签名密钥和构建产物的 Git 忽略规则见 `.gitignore`。

## 回归验证

先构建并安装当前 APK，再运行以下命令。存储测试使用内存配置及真实 AndroidKeyStore，覆盖旧配置迁移、独立 Key、编辑、开关、异常输入、删除、旧接口和并发保存。`--ui` 通过实际按钮和对话框验证新增、重开、切换、未保存修改及删除，并在结束后恢复原配置。

```powershell
python tests/run.py --adb '<adb.exe 的完整路径>' --device '<设备序列号>' --ui
```

需要核实当前服务商的输出截断时，可运行下面的诊断。它使用当前保存的模型与 Key，发送两次合成的 50 行长文本请求，分别比较旧版 512-token 限制和当前正常模型入口的结束原因、长度及末尾标记。诊断会产生实际模型用量。

```powershell
python tests/run.py --adb '<adb.exe 的完整路径>' --device '<设备序列号>' --diagnose-output
```

0.1.9 已通过 32 项手机端回归，包括模型列表 GET 请求、鉴权与路径、空列表和错误响应、旧模型迁移、同供应商多模型保存和切换、并发添加、搜索筛选后的多选状态，以及官方原生完成和错误回调。当前保存的真实中转站实测返回 17 个模型，包含当前模型。`tests/run.py --diagnose-models` 可以读取当前供应商的实际模型列表，诊断输出数量及当前模型是否在列表中。
